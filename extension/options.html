Catching up quickly

Fast-forward changes scrolling only: bigger jumps and shorter waits while skimming past posts you have already liked. Clicks keep their full randomised pacing and the safety checks are untouched.

Keeping a huge feed responsive

An infinite feed never throws anything away, so on a catch-up run the tab ends up holding thousands of cards and avatars until Chrome hangs. With this on, posts you have already finished with, and that are scrolled well above the visible feed, are removed from the page as you go. Only already-processed, off-screen cards are ever touched — never a post still waiting to be liked, never anything on screen, and never the most recent cards. The scroll position is corrected so the view does not jump. It only changes what your browser is holding in memory; nothing is changed on RecognizeApp.

Page-by-page mode

The Recognize grid exposes real pagination (?page=N, a “next” link, a pagination block at the bottom). When it does, this walks it a page at a time instead of scrolling: each page is a small, fresh document, so nothing bloats and the tab stops hanging — and because progress is just a page number, a run resumes where it left off instead of reloading from the top.

Moving to the next page is a real navigation, so the tab's address changes as it goes. Progress is saved before every hop, so a reload or a closed tab loses at most the current page. Every filter already applied to the feed is carried across. If a page has no pagination this does nothing and scrolling is used instead.

Running in the background

Chrome slows tabs you are not looking at — timer chains drop to about once a second, and to about once a minute after five minutes hidden. Two things push back:

Always on: the extension's service worker is woken by an alarm and pings the tab, which settles any wait Chrome already owed it. This can never make a click happen sooner than its own delay allowed.

This checkbox: additionally holds an inaudible Web Audio tone while a run is in progress. Chrome keeps tabs that are producing audio fully awake and will not freeze or discard them. Honest trade-off: the tab shows a speaker icon, appears in Chrome's media controls, and holds an audio output open. It stops the moment the run stops. If the page has not been clicked since it loaded, Chrome's autoplay policy keeps it suspended until you click anywhere on the feed once.

Neither helps if Windows sleeps or hibernates, or if Chrome is closed. Nothing here changes your power settings.

Interface

Processing history

History is a list of recognition IDs this extension has already processed. It exists purely to save work — skipping items that have repeatedly failed, and keeping your totals across page reloads. It never decides whether a recognition is liked. That is read from the page's DOM every single time, immediately before every click. Clearing history is always safe: at worst the extension re-examines items it has seen before.
