# Recognize Auto Liker — বাংলা নির্দেশিকা

RecognizeApp-এর recognition ফিডে যে পোস্টগুলোতে আপনি **এখনো Like দেননি**, শুধু সেগুলোর
Like (`+`) বাটনে ক্লিক করার জন্য একটি **লোকাল** ব্রাউজার অটোমেশন টুল।

এটি আপনার নিজের খোলা ও নিজে লগইন করা ব্রাউজার ট্যাবের ভেতরেই চলে।

### যা এই টুল ইচ্ছাকৃতভাবে করে না

| যা করা হয়নি | কারণ |
| --- | --- |
| লগইন অটোমেশন | আপনি নিজে ম্যানুয়ালি লগইন করবেন |
| পাসওয়ার্ড/ক্রেডেনশিয়াল সংরক্ষণ | কখনোই স্পর্শ করা হয় না |
| কুকি এক্সট্র্যাকশন | কখনোই পড়া বা রপ্তানি করা হয় না |
| অথেনটিকেশন বাইপাস | কখনোই চেষ্টা করা হয় না |
| API টোকেন বা সরাসরি API কল | শুধু দৃশ্যমান DOM এলিমেন্টে ক্লিক করে |
| রান স্টেট সংরক্ষণ | পেজ রিফ্রেশ করলেই অটোমেশন সম্পূর্ণ রিসেট হয় |

## ১. কোন আর্কিটেকচার বেছে নেওয়া হয়েছে এবং কেন

**একটি মাত্র সোর্স ফাইল থেকে তৈরি একটি স্বয়ংসম্পূর্ণ স্ক্রিপ্ট, চারটি ইনস্টল-পদ্ধতিতে।**

```
src/recognize-auto-liker.js        <-- মূল ইঞ্জিন (একমাত্র সোর্স)
        |
        +--> userscript/...user.js       (Tampermonkey)     <-- সুপারিশকৃত
        +--> dist/console-snippet.js     (DevTools-এ পেস্ট)  <-- ইনস্টল ছাড়াই চলে
        +--> dist/bookmarklet.txt        (বুকমার্কলেট)
        +--> extension/                  (আনপ্যাকড ক্রোম এক্সটেনশন)
```

**কেন এই ডিজাইন:** আপনার অফিসের Chrome কিছু Web Store এক্সটেনশন ব্লক করে। তাই মূল
শর্ত ছিল — *"ইনস্টল ব্লক থাকলেও যেন কাজ করে"*।

* **DevTools কনসোলে পেস্ট করা কখনোই এক্সটেনশন পলিসি দিয়ে ব্লক করা যায় না।** তাই
  ইঞ্জিনটি একটিমাত্র স্বয়ংসম্পূর্ণ IIFE হিসেবে লেখা — কোনো বিল্ড স্টেপ, import,
  bundler বা নেটওয়ার্ক ফেচ নেই। পেস্ট করলেই চলে।
* **Tampermonkey** প্রতিদিনের ব্যবহারের জন্য সবচেয়ে সুবিধাজনক (প্রতিবার পেজ খুললেই
  নিজে থেকে লোড হয়) — একই ফাইল, শুধু উপরে metadata হেডার যোগ করা।
* **আনপ্যাকড এক্সটেনশন** — যদি Tampermonkey ব্লক থাকে কিন্তু Developer mode খোলা থাকে।
* **Playwright-কে প্রধান পদ্ধতি হিসেবে নেওয়া হয়নি**, কারণ এটি **আলাদা** ব্রাউজার
  প্রোফাইল চালায়, ফলে লগইন অটোমেশন লাগত — যা আপনি স্পষ্টভাবে নিষেধ করেছেন। এখানে
  Playwright শুধু **টেস্ট সুইট** চালাতে ব্যবহৃত হয়েছে, লোকাল মক পেজের বিপরীতে।

কোনো পদ্ধতিই অফিসের অ্যাডমিন রেস্ট্রিকশন বাইপাস করে না। চারটি পথই যদি পলিসিতে বন্ধ
থাকে, তাহলে সঠিক কাজ হলো IT-কে জিজ্ঞাসা করা — ঘুরপথ বের করা নয়।

## ৩. Windows-এ ইনস্টল করার নিয়ম

### পদ্ধতি A — Tampermonkey (সুপারিশকৃত)

1. Chrome-এ (Web Store) অথবা Edge-এ (Edge Add-ons — Chrome স্টোর বন্ধ থাকলেও প্রায়ই
   এটি খোলা থাকে) **Tampermonkey** ইনস্টল করুন।
2. Tampermonkey ড্যাশবোর্ড → **Utilities** ট্যাব → **File** → `userscript\recognize-auto-liker.user.js`
   ফাইলটি বেছে নিন → **Install**।
   *(অথবা: ড্যাশবোর্ড → `+` → টেমপ্লেটটা মুছে দিন → পুরো ফাইলটা পেস্ট করুন → `Ctrl+S`)*
3. RecognizeApp খুলুন। ডান দিকে উপরে **Recognize Auto Liker** প্যানেল দেখা যাবে।

### পদ্ধতি B — DevTools কনসোল (সবসময় কাজ করে, ইনস্টল লাগে না)

1. Chrome-এ RecognizeApp খুলে **নিজে ম্যানুয়ালি লগইন** করুন।
2. `F12` চাপুন → **Console** ট্যাবে যান।
3. Chrome যদি "Allow pasting" সতর্কতা দেখায়, তাহলে `allow pasting` লিখে Enter চাপুন।
4. `dist\console-snippet.js` ফাইলটি Notepad-এ খুলুন → `Ctrl+A` → `Ctrl+C`।
5. Console-এ পেস্ট করে Enter চাপুন। প্যানেল চলে আসবে।
6. মনে রাখবেন: পেজ রিফ্রেশ বা নেভিগেট করলে এটি চলে যাবে — আবার পেস্ট করতে হবে।

### পদ্ধতি C — বুকমার্কলেট

1. Chrome → `Ctrl+Shift+O` (Bookmark manager) → ⋮ → **Add new bookmark**।
2. Name: `Recognize Auto Liker`। URL: `dist\bookmarklet.txt` ফাইলের **পুরো এক লাইন**।
3. RecognizeApp পেজে গিয়ে বুকমার্কে ক্লিক করুন।
   *(কিছু সাইটের Content-Security-Policy বুকমার্কলেট ব্লক করতে পারে; কিছু না হলে পদ্ধতি B ব্যবহার করুন।)*

### পদ্ধতি D — আনপ্যাকড ক্রোম এক্সটেনশন

1. `chrome://extensions` খুলুন → উপরে ডানে **Developer mode** চালু করুন।
2. **Load unpacked** → `extension\` ফোল্ডারটি বেছে নিন।
3. RecognizeApp খুললেই প্যানেল নিজে থেকে লোড হবে।
   *(অফিসের পলিসি যদি Developer mode বন্ধ রাখে, তাহলে পদ্ধতি B ব্যবহার করুন।)*

## ৪. ডায়াগনস্টিক মোড চালানো (সবার আগে এটি করুন)

ডায়াগনস্টিক মোড **কোনো ক্লিক করে না**। শুধু কী কী দেখতে পাচ্ছে তা রিপোর্ট করে।

**প্যানেল থেকে:** **RUN DIAGNOSTIC (no clicks)** বাটনে ক্লিক করুন, তারপর `F12` চেপে
Console-এ পুরো রিপোর্ট দেখুন। (অথবা **Diagnostic mode** টিক দিয়ে **START** চাপলে সে
শুধু স্ক্যান করে থেমে যাবে।)

**কনসোল থেকে:**

```js
__RecognizeAutoLiker__.diagnose()
```

যা রিপোর্ট করে:

```
[RecognizeAutoLiker] DIAGNOSTIC (no clicks performed)
  Unliked recognitions: 12
  Liked recognitions:   8
  Feed scroll container: <div id="feed-scroller">
  Current scroll height: 5840
  Current viewport height: 720
  Recognition ID: rglauokd   Approval href: /banglalink.net/recognitions/rglauokd/approvals?approvers_limit=5
```

**যদি `Unliked recognitions: 0` দেখায় অথচ চোখে না-লাইক-করা পোস্ট দেখা যাচ্ছে** — তাহলে
এখানেই থামুন। আপনার টেন্যান্টের জন্য সিলেক্টর ঠিক করতে হবে; প্রোডাকশন মোডেও কিছুই হবে না।

## ৫. প্রোডাকশন মোড চালানো

1. আগে নিশ্চিত করুন ডায়াগনস্টিক মোড যুক্তিসঙ্গত সংখ্যক unliked recognition পেয়েছে।
2. **Max likes** (ডিফল্ট `500`) এবং **Delay** (ডিফল্ট `1000` ms) ঠিক করুন।
3. **START** চাপুন।

অথবা কনসোল থেকে:

```js
__RecognizeAutoLiker__.start({ maxLikes: 50, baseDelay: 1200 });
```

**প্রতি চক্রে যা করে:** দৃশ্যমান unliked approval খোঁজে → ৫০০–১২০০ ms অপেক্ষা → ক্লিক →
৮০০–১৮০০ ms অপেক্ষা → `.unapproved` থেকে `.approved` হয়েছে কিনা **যাচাই** করে → পরেরটিতে
যায় → ফিডের উচ্চতার ৬০–৭৫% স্ক্রল করে → নতুন কার্ডের জন্য ১৫০০–২৫০০ ms অপেক্ষা → আবার শুরু।

**Delay** একটি ভিত্তি-মান: উপরের প্রতিটি র‍্যান্ডম রেঞ্জ এর সাথে অনুপাতে বাড়ে/কমে।
`2000` দিলে সব দ্বিগুণ, `500` দিলে সব অর্ধেক।

**নিজে থেকেই থামে যখন:** Max likes পূর্ণ হয়, অথবা টানা ৫ বার স্ক্রল করেও নতুন কিছু
আসে না (পরিবর্তনযোগ্য), অথবা আপনি **STOP** চাপেন।

## ৬. থামানোর উপায়

| উপায় | ফল |
| --- | --- |
| **STOP** বাটন | সাথে সাথে। আর একটিও ক্লিক যাবে না। |
| **`Esc`** কী | STOP-এর সমান — জরুরি স্টপ, পেজের যেকোনো জায়গা থেকে কাজ করে। |
| **PAUSE** বাটন | চলমান ক্লিকটি শেষ ও যাচাই হবে; নতুন ক্লিক শুরু হবে না। **RESUME** চেপে আবার চালু। |
| **রিফ্রেশ / নেভিগেট** | অটোমেশন পুরোপুরি মুছে যায়। কিছুই সংরক্ষিত থাকে না। |
| কনসোল | `__RecognizeAutoLiker__.stop()` / `.pause()` / `.resume()` |

STOP **প্রতিটি** ক্লিকের আগে এবং প্রতিটি অপেক্ষার ভেতরে চেক করা হয়, তাই এটি চলমান
ডিলে শেষ হওয়ার অপেক্ষা না করে প্রায় ১০০ ms-এর মধ্যেই কার্যকর হয়।

## ৭. কনফিগারেশন

প্যানেলে: **Max likes**, **Delay**, **No-new-content stop**, **Diagnostic mode**।
বাকি সব কনসোল থেকে:

```js
__RecognizeAutoLiker__.setConfig({
  maxLikes: 500,
  baseDelay: 1000,               // ms; নিচের সব র‍্যান্ডম রেঞ্জ এর সাথে স্কেল করে
  preClickDelayRange:   [500, 1200],
  postClickDelayRange:  [800, 1800],
  postScrollDelayRange: [1500, 2500],
  scrollFractionRange:  [0.60, 0.75],  // প্রতি স্ক্রলে ফিড-উচ্চতার কত অংশ
  maxNoNewContentAttempts: 5,          // ফিড শেষ ধরার সীমা
  verifyTimeoutMs: 2500,               // .approved নিশ্চিত করার সময়সীমা
  maxRetriesPerRecognition: 1,         // একবারই রিট্রাই, তারপর failed
  scrollIntoViewBeforeClick: true,
  diagnostic: false,
  verbose: true
});

__RecognizeAutoLiker__.stats();        // { detected, liked, alreadyLiked, skipped, failed, scrolls }
__RecognizeAutoLiker__.processedIds(); // যেগুলো ইতিমধ্যে হ্যান্ডেল করা হয়েছে
__RecognizeAutoLiker__.failedIds();    // যেগুলো কিছুতেই approved হয়নি
```

## ৮. নিরাপত্তা — এটি "যদি আগে লাইক না করা থাকে তবেই লাইক" টুল, "টগল লাইক" টুল নয়

ইতিমধ্যে approved কন্ট্রোলে ক্লিক করলে সেটি `DELETE` পাঠায় এবং **আপনার নিজের আগের
লাইকটি মুছে ফেলে**। এটিই একমাত্র ভুল যা "কিছু না হওয়া" নয়, বরং **ডেটা নষ্ট করে** —
তাই এটি কাঠামোগতভাবেই আটকানো হয়েছে।

### দুইটি অবস্থা

| | ক্লাস | `data-method` | href | করণীয় |
| --- | --- | --- | --- | --- |
| আপনি লাইক করেননি | `approval_link unapproved` | `post` | `/recognitions/<id>/approvals` | **ক্লিক** |
| আপনি লাইক করেছেন | `approval_link approved` | `delete` | `/recognitions/<id>/approvals/<approval_id>` | **কিছুই না** |

### `+N` সংখ্যাটি লাইক-অবস্থার সংকেত নয়

লিংকের ভেতরের সংখ্যা (`+1`, `+4`, `+5`) হলো **সব ইউজারের মোট approval সংখ্যা**। এটি
দিয়ে বোঝা যায় না *আপনি* লাইক করেছেন কিনা — একটি না-লাইক-করা পোস্টেও `+4` থাকতে পারে,
আর লাইক করার পর সেটি `+5` হয়। তাই ইঞ্জিন **কোনো সিদ্ধান্তে লিংকের টেক্সট পড়েই না**।
`src/recognize-auto-liker.js`-এ কন্ট্রোল প্যানেলের নিজের UI ছাড়া কোথাও
`textContent`/`innerText` পড়া নেই — grep করে দেখতে পারেন। `data-sender`-ও সংকেত নয়,
কারণ সেটি দুই অবস্থাতেই পূরণ থাকে।

টেস্ট ১৪ ইচ্ছা করে বিভ্রান্তিকর ফিক্সচার দিয়ে এটি প্রমাণ করে: দুটি recognition-এই
`+4` দেখাচ্ছে, একটি unliked আরেকটি liked। unliked-টায় ক্লিক হতেই হবে, liked-টায়
কিছুতেই নয়।

### কঠোর গেট (Hard gate)

**ক্লিকের ঠিক আগমুহূর্তে নতুন করে DOM query** করে নিচের **প্রতিটি** শর্ত মিললে তবেই ক্লিক:

* এলিমেন্টটি এখনো ডকুমেন্টে যুক্ত (`isConnected`)
* এটি একটি `<a>` ট্যাগ
* ক্লাসে `approval_link` আছে
* **`.approved` নেই এবং `data-method="delete"` নয়** ← সবার আগে এই দুটি বাতিল করা হয়
* ক্লাসে `unapproved` আছে
* `data-method === "post"`
* `data-category === "recognition"`
* `data-event === "liked"`
* সম্মিলিত সিলেক্টর `SELECTORS.UNLIKED`-ও মেলে
* `href`-এ `/recognitions/<id>/approvals` আছে, `<id>` হলো `[A-Za-z0-9_-]+`
* দৃশ্যমান: শূন্য নয় এমন আকার, `display:none` / `visibility:hidden` / `opacity:0` / `pointer-events:none` নয়
* সক্রিয়: `disabled` নেই, `aria-disabled="true"` নেই, `.disabled` নেই

**একটি শর্তও না মিললে, বা এলিমেন্টটি নতুন করে যাচাই করা না গেলে — ক্লিক হবে না।**

এই গেট **তিনবার** চলে: স্ক্যানের সময়, pre-click ডিলের পরে (মাঝে ফিড বদলে যেতে পারে),
এবং তৃতীয়বার `performClick()`-এর ভেতরে `el.click()`-এর **ঠিক আগে, শূন্য ব্যবধানে** —
যাতে কোনো await, timer, retry বা ভবিষ্যতের রিফ্যাক্টর চেক আর ক্লিকের মাঝে কিছু ঢোকাতে
না পারে। `performClick()` সম্পূর্ণ যাচাই করতে না পারলে ক্লিক না করে **throw** করে, এবং
পুরো ফাইলে ক্লিক পাঠানোর একমাত্র জায়গা এটিই।

কমেন্ট approval (`data-category="comment"`), ভুল-event approval, নেভিগেশন, প্রোফাইল
লিংক, recognition তৈরির বাটন, এবং ইতিমধ্যে approved কন্ট্রোল — সবই কাঠামোগতভাবে বাদ।

### ইন-মেমরি Set গৌণ

processed-ID `Set` শুধু **ডুপ্লিকেট প্রতিরোধের** জন্য। এটি কখনোই ক্লিক করার *কারণ* নয় —
DOM-এর বর্তমান অবস্থাই চূড়ান্ত, এবং Set যা-ই বলুক, উপরের পুরো গেট প্রতিবার নতুন
query-র বিপরীতে চলে।

## ৯. Idempotency ও ডুপ্লিকেট প্রতিরোধ

একই ফিডে প্রতিদিন চালানো নিরাপদ। আগে লাইক করা কোনো recognition পরবর্তী রানে
**কখনোই আন-লাইক হবে না**।

* প্রতিটি recognition ID (`href` থেকে নেওয়া) একবার হ্যান্ডেল হলেই `Set`-এ জমা হয়।
* যা-ই approved মনে হয় — `.approved` **অথবা** `data-method="delete"`, যেকোনো একটি
  সংকেত থাকলেই — সেটি already-liked ধরে নিয়ে কখনো ক্লিক করা হয় না। অস্পষ্ট বা
  আধা-রেন্ডার হওয়া এলিমেন্ট বাদ দেওয়া হয়, ক্লিক করা হয় না।
* ক্লিকের পর ধরে নেওয়া হয় না — **নির্দিষ্ট প্রত্যাশিত রূপান্তরটি যাচাই** করা হয়: একই
  recognition এখন
  `a.approval_link.approved[data-category="recognition"][data-event="liked"][data-method="delete"]`
  -এর সাথে মিলতে হবে এবং unapproved সিলেক্টরের সাথে আর মেলা যাবে না। `href`-এ
  `/approvals/<approval_id>` যুক্ত হয়েছে কিনা তা লগে নিশ্চিতকরণ হিসেবে দেখানো হয়।
* রূপান্তর না হলে **ঠিক একবার** রিট্রাই, তারপর failed চিহ্নিত করে সামনে এগোয়।
  তৃতীয়বার ক্লিকের কোনো কোড-পথই নেই।
* এলিমেন্ট হারিয়ে গিয়ে ফলাফল প্রমাণ করা না গেলে সেটিকে অনিশ্চিত ধরে বাদ দেওয়া হয় —
  আবার ক্লিক করা হয় না।

টেস্ট ১৩ একই ফিডে ইঞ্জিন দুইবার চালায় ("Day 1" / "Day 2") এবং প্রমাণ করে যে দ্বিতীয়
রানে **শূন্যটি** ক্লিক যায় এবং DOM হুবহু অপরিবর্তিত থাকে — approval ID সহ।

## ১১. সমস্যা সমাধান (Troubleshooting)

**প্যানেল আসছে না**
কনসোল পেস্টের ক্ষেত্রে: লাল এরর আছে কিনা দেখুন, এবং আগে `allow pasting` লিখেছেন কিনা।
Tampermonkey-তে: স্ক্রিপ্ট enabled কিনা এবং `@match` আপনার হোস্টের সাথে মেলে কিনা দেখুন।
আপনার URL যদি `*.recognizeapp.com` না হয়, `@match` লাইনটি আপনার আসল ডোমেইনে বদলে দিন।

**`Unliked recognitions: 0` অথচ চোখে unliked পোস্ট দেখা যাচ্ছে**
একটি `+` বাটনে ডান-ক্লিক → Inspect → ক্লাস ও `data-` অ্যাট্রিবিউট মিলিয়ে দেখুন। ভিন্ন হলে
`src/recognize-auto-liker.js`-এ `SELECTORS.UNLIKED` বদলে `node tools/build.cjs` চালান।

**কয়েকটা লাইক করেই খুব তাড়াতাড়ি `END_OF_FEED` বলে থেমে যায়**
ফিডের lazy loading অপেক্ষার চেয়ে ধীর। ডিলে বাড়ান:
`setConfig({ baseDelay: 2000, maxNoNewContentAttempts: 8 })`।

**স্ক্রল কন্টেইনার `window` দেখাচ্ছে কিন্তু ফিড নড়ছে না**
ডায়াগনস্টিক মোড কোন কন্টেইনার বেছেছে তা ছাপে। ভুল হলে ফিডটি একবার হাতে স্ক্রল করুন
(যাতে স্ক্রলবার তৈরি হয়) তারপর আবার `diagnose()` চালান।

**সবকিছুতেই `failed` দেখাচ্ছে**
ক্লিক যাচ্ছে কিন্তু সার্ভার approve করছে না। Network ট্যাবে `POST /approvals` রিকোয়েস্ট
ফেল করছে কিনা দেখুন — এটি সার্ভার/পারমিশনের সমস্যা, অটোমেশনের নয়। থামুন এবং দেখুন
আপনার অ্যাকাউন্ট আদৌ ঐ পোস্টগুলোতে লাইক দিতে পারে কিনা।

**রিফ্রেশের পর গণনা শূন্য হয়ে যায়**
এটি ইচ্ছাকৃত — কিছুই সংরক্ষিত হয় না। রিফ্রেশের পর ইঞ্জিন শূন্য থেকে শুরু করে এবং
DOM-এর `.approved` অবস্থা দেখেই বোঝে কোনটা আগে থেকেই লাইক করা — এটিই সঠিক আচরণ।

**ক্লিক হচ্ছে কিন্তু কিছু বদলাচ্ছে না, কনসোলে Rails UJS এরর**
অ্যাপটি `data-remote="true"` (Rails UJS) ব্যবহার করে। ইঞ্জিন অ্যাংকরে আসল `click()`
পাঠায়, যা UJS-ই শোনে। অ্যাপের JS পুরো লোড না হলে সমস্যা হতে পারে — ফিড সম্পূর্ণ
রেন্ডার হওয়ার পর START চাপুন।

## ১২. জানা সীমাবদ্ধতা

* recognition ID-র একমাত্র উৎস `href`। কোনো টেন্যান্টে যদি `href`-এ
  `/recognitions/<id>/approvals` না থাকে, সেটিকে অন্ধভাবে ক্লিক না করে safety gate
  বাদ দিয়ে দেবে (`no-recognition-id-in-href`)।
* "লাইক হয়েছে" — এই নিশ্চয়তা DOM যতটুকু দেয় ততটুকুই। অ্যাপ যদি সার্ভারের উত্তরের
  আগেই আশাবাদীভাবে `.approved` দেখায় এবং পরে রিকোয়েস্ট ফেল করে, ইঞ্জিন সেটিকে
  liked হিসেবেই গুনবে।
* সার্ভারের rate limiting DOM থেকে বোঝা যায় না। লাইক নীরবে কাজ না করলে ইঞ্জিন
  `failed` রিপোর্ট করবে — সেটিই থেমে যাওয়ার সংকেত।
* কনসোল-পেস্ট পদ্ধতি পেজ রিফ্রেশের পর টেকে না (ইচ্ছাকৃত)।
* শুধু মূল ডকুমেন্ট হ্যান্ডেল করা হয় (`@noframes`); iframe-এর ভেতরের recognition বাদ যায়।
* ধরে নেওয়া হয়েছে সব recognition একটিমাত্র স্ক্রলযোগ্য কন্টেইনারে থাকে। একাধিক
