# Recognize Auto Liker — বাংলা নির্দেশিকা

RecognizeApp-এর যে recognition পোস্টগুলোতে আপনি **এখনো Like দেননি**, সেগুলোতে
স্বয়ংক্রিয়ভাবে Like দেয় এবং ফিড স্ক্রল করে — আর **আগে দেওয়া কোনো Like কখনোই মুছে ফেলে না**।

সবকিছু আপনার নিজের খোলা ও নিজে লগইন করা ব্রাউজার ট্যাবেই চলে। লগইন অটোমেশন নেই,
পাসওয়ার্ড/কুকি/টোকেন ধরা হয় না, কোনো সার্ভারও নেই।

## ১. দুইভাবে চালানো যায়

### ক) Chrome এক্সটেনশন — প্রধান পদ্ধতি

পুরোপুরি Manifest V3। **Node লাগে না, npm লাগে না, বিল্ড স্টেপ নেই, সার্ভার নেই,
কোনো সফটওয়্যার ইনস্টল করতে হয় না।**

```
chrome://extensions → Developer mode চালু → Load unpacked → `extension` ফোল্ডারটি বেছে নিন
```

তারপর RecognizeApp খুলে **নিজে লগইন করুন**, এক্সটেনশন আইকনে ক্লিক করে **START** চাপুন।

**→ পূর্ণ নির্দেশিকা: [`extension/README.md`](extension/README.md)**

### খ) বিকল্প — যদি unpacked এক্সটেনশন ব্লক থাকে

> **`Extension installation is blocked by policy` দেখাচ্ছে?** এটি আপনার অফিসের Chrome
> পলিসি, এবং এখানকার কিছুই সেটি বাইপাস করার চেষ্টা করে না। নিচের console snippet
> ব্যবহার করুন — এটি একই ইঞ্জিন, এক্সটেনশন নয়, এবং একই টেস্ট স্যুটে যাচাই করা।
> কোন পলিসি দায়ী দেখতে `chrome://policy` খুলে `ExtensionInstallBlocklist` /
> `ExtensionSettings` খুঁজুন।
>
> **দ্রুততম পথ:** Recognize ফিড খুলুন → `F12` → **Console** → Chrome চাইলে
> `allow pasting` লিখে Enter → `dist/console-snippet.js`-এর **পুরোটা** পেস্ট করে Enter।
> ডানদিকে উপরে একটি কন্ট্রোল প্যানেল আসবে। আগে **RUN DIAGNOSTIC** চাপুন, তারপর
> *Max new likes* ৩–৫ দিয়ে **START**। থামাতে `Esc`। পেজ রিলোড করলে আবার পেস্ট করতে হবে।

কিছু অফিসের Chrome পলিসি Developer mode বন্ধ রাখে। সেক্ষেত্রে একই ইঞ্জিন এই তিন রূপেও আছে:

| ফাইল | ব্যবহার |
| --- | --- |
| `dist/console-snippet.js` | `F12` → Console → দরকার হলে `allow pasting` লিখে Enter → পুরোটা পেস্ট → Enter। **এটি এক্সটেনশন পলিসি দিয়ে ব্লক করা যায় না** |
| `userscript/recognize-auto-liker.user.js` | Tampermonkey → Utilities → File → Install |
| `dist/bookmarklet.txt` | পুরো এক লাইন একটি বুকমার্কের URL হিসেবে বসান |

এগুলোতে popup-এর বদলে একটি ভাসমান কন্ট্রোল প্যানেল আসে। এগুলো **এক্সটেনশনের ইঞ্জিন থেকেই
তৈরি** (`node tools/build.cjs`), তাই ক্লিক-নিরাপত্তার নিয়ম পুরো রিপোতে **একটাই জায়গায়** আছে।

কোনো পদ্ধতিই অ্যাডমিন রেস্ট্রিকশন বাইপাস করে না। সব পথ বন্ধ থাকলে সঠিক কাজ হলো IT-কে বলা।

## ২. ইনস্টল (Windows, অ্যাডমিন লাগে না)

1. প্রজেক্ট ফোল্ডারটি আনজিপ করুন, যেমন `C:\Users\you\recognize`।
2. **`chrome://extensions`** খুলুন।
3. উপরে ডানে **Developer mode** চালু করুন।
4. **Load unpacked** চাপুন।
5. **`extension`** ফোল্ডারটি বেছে নিন (যেটির ভেতরে `manifest.json` আছে) — প্রজেক্টের রুট নয়।
6. RecognizeApp খুলে **স্বাভাবিকভাবে লগইন করুন**।
7. ফিড খুলুন → এক্সটেনশন আইকনে ক্লিক → **START**।

Chrome-এর বাইরে কিছুই ইনস্টল হয় না। Windows সেটিংস, Chrome পলিসি বা নিরাপত্তা
নিয়ন্ত্রণে কোনো পরিবর্তন করা হয় না।

**আপডেট করতে:** ফোল্ডারের ফাইল বদলে `chrome://extensions`-এ গিয়ে reload (↻) চাপুন।
আপনার সেটিংস ও history থেকে যাবে।

## ৪. নিরাপত্তা — এটি "টগল লাইক" টুল নয়

**এটি "আগে লাইক না করা থাকলে তবেই লাইক" টুল।** ইতিমধ্যে approved কন্ট্রোলে ক্লিক করলে
সেটি `DELETE` পাঠায় এবং **আপনার নিজের লাইক মুছে ফেলে** — এটিই একমাত্র ভুল যা "কিছু না
হওয়া" নয়, বরং ডেটা নষ্ট করে। তাই এটি কাঠামোগতভাবেই আটকানো।

| | ক্লাস | `data-method` | করণীয় |
| --- | --- | --- | --- |
| আপনি লাইক করেননি | `approval_link unapproved` | `post` | **ক্লিক** |
| আপনি লাইক করেছেন | `approval_link approved` | `delete` | **কিছুই না** |

### `+N` সংখ্যাটি লাইক-অবস্থার সংকেত নয়

ভেতরের সংখ্যা (`+1`, `+4`, `+5`) হলো **সব ইউজারের মোট approval**। এটি বলে না *আপনি*
লাইক করেছেন কিনা: একটি unliked পোস্টেও `+4` থাকতে পারে, লাইক করার পর `+5` হয়। দুটি
recognition-ই `+4` দেখাতে পারে, অথচ একটিতে ক্লিক করতে হবে আর অন্যটিতে কিছুতেই নয়।

তাই এক্সটেনশন **কোনো সিদ্ধান্তে কন্ট্রোলের টেক্সট পড়েই না**। `data-sender`-ও সংকেত নয়,
কারণ সেটি দুই অবস্থাতেই পূরণ থাকে।

### কঠোর গেট

**ক্লিকের ঠিক আগমুহূর্তে নতুন করে DOM query** করে নিচের **প্রতিটি** শর্ত মিললে তবেই ক্লিক:
এলিমেন্ট ডকুমেন্টে যুক্ত, `<a>` ট্যাগ, ক্লাসে `approval_link`, **`approved` নেই**,
**`data-method="delete"` নয়**, ক্লাসে `unapproved`, `data-category="recognition"`,
`data-event="liked"`, `data-method="post"`, সম্মিলিত সিলেক্টরও মেলে, `href` থেকে
recognition ID পাওয়া যায়, দৃশ্যমান, সক্রিয়, এবং recognition কার্ডের ভেতরে।

**একটি শর্তও না মিললে — ক্লিক হবে না।**

গেটটি প্রতি ক্লিকে **তিনবার** চলে: স্ক্যানের সময়, pre-click ডিলের পরে, এবং তৃতীয়বার
`performClick()`-এর ভেতরে `el.click()`-এর **ঠিক আগে, শূন্য ব্যবধানে**। পুরো ইঞ্জিনে
ক্লিক পাঠানোর একমাত্র জায়গা ওটিই — দ্বিতীয় কোনো `.click()` যোগ হলে টেস্ট ফেল করে।

**ক্লিকের পরে** সেই recognition-কে ID ধরে আবার খুঁজে নির্দিষ্ট রূপান্তর যাচাই করা হয়:
`unapproved + post` → `approved + delete`। না হলে **ঠিক একবার** রিট্রাই, তারপর error
হিসেবে চিহ্নিত করে সামনে এগোয়। তৃতীয়বার ক্লিকের কোনো পথই নেই।

### History কখনোই ক্লিকের কারণ নয়

`chrome.storage.local`-এ প্রসেস করা recognition ID-র তালিকা রাখা হয় — শুধু **হিসাব ও
দক্ষতার জন্য**। এটি কেবল *skip* করাতে পারে, কখনো ক্লিক করাতে পারে না:

| History বলে | DOM বলে | ফল |
| --- | --- | --- |
| liked | `unapproved` + `post` | **লাইক হবে** — DOM জেতে |
| liked নয় | `approved` + `delete` | **বাদ** — DOM জেতে |

History মুছে ফেলা সবসময় নিরাপদ (**Options → Clear history**)।

## ৫. মিনিমাইজ/ব্যাকগ্রাউন্ডে চলা — সৎ কথা

এক্সটেনশনটি এমনভাবে বানানো যে ট্যাব দেখতে হয় না: সবকিছু content script-এ সরাসরি DOM
নিয়ে কাজ — `requestAnimationFrame` নেই, স্ক্রিন কো-অর্ডিনেট নেই, মাউস/কীবোর্ড সিমুলেশন
নেই, স্ক্রিনশট নেই। **`document.hidden` বা `visibilityState` কখনোই দেখা হয় না**, তাই
ব্যাকগ্রাউন্ডে গেলে থেমে যায় না। প্রতিটি অপেক্ষা **একটিমাত্র টাইমার** — ছোট টাইমারের
চেইন নয় (চেইন হলে ব্যাকগ্রাউন্ডে throttle-এর কারণে ১.৫ সেকেন্ড কয়েক মিনিট হয়ে যেত)।

**তবে গুরুত্বপূর্ণ সীমাবদ্ধতা:** Chrome এক্সটেনশন ব্যাকগ্রাউন্ডে চলার **নিশ্চয়তা দিতে
পারে না**, আর এই প্রজেক্ট সেই দাবিও করে না।

* লুকানো ট্যাবে Chrome টাইমার throttle করে (কয়েক মিনিট পর প্রায় মিনিটে একবার)। রান
  চলতে থাকে, কিন্তু **ধীরে**। popup সেটা সৎভাবে `RUNNING (throttled)` দেখায়।
* Windows স্লিপ/হাইবারনেট করলে, Chrome বন্ধ হলে, বা মেমরির চাপে ট্যাব discard হলে
  অটোমেশন থেমে যায়।
* Chrome-এর throttling বা কোনো নিরাপত্তা ব্যবস্থা বাইপাস করার চেষ্টা করা হয়নি।

**দ্রুত ও নির্ভরযোগ্য রানের জন্য ট্যাবটি সামনে খোলা রাখুন।**

| `host_permissions` (শুধু recognizeapp.com) | content script শুধু আপনার Recognize ফিডে চলে |

**চাওয়া হয়নি:** `<all_urls>`, `tabs`, `cookies`, `webRequest`, `scripting`, `history`।
RecognizeApp ছাড়া অন্য কোনো সাইটে এক্সটেনশনটি সম্পূর্ণ নিষ্ক্রিয়।

**কোনো ডেটা ব্রাউজারের বাইরে যায় না** — ব্যাকএন্ড নেই, analytics নেই, কোনো নেটওয়ার্ক
রিকোয়েস্টই নেই। এটি স্বয়ংক্রিয় চেক দিয়ে নিশ্চিত করা: `extension/`-এর কোথাও `fetch`,
`XMLHttpRequest`, `document.cookie`, `chrome.cookies` বা `navigator.credentials` থাকলে
টেস্ট ফেল করে। পাসওয়ার্ড, কুকি, সেশন/SSO টোকেন, ব্রাউজিং history — কিছুই স্পর্শ করা হয় না।

## ৮. জানা সীমাবদ্ধতা

* **ব্যাকগ্রাউন্ড এক্সিকিউশনের নিশ্চয়তা নেই** (উপরে §৫ দেখুন)।
* "লাইক হয়েছে" নিশ্চয়তা DOM যতটুকু দেয় ততটুকুই। সন্দেহ হলে ইঞ্জিন *ক্লিক না করার*
  দিকেই ঝোঁকে — সবচেয়ে খারাপ ফল একটি লাইক বাদ পড়া, কখনোই একটি লাইক মুছে যাওয়া নয়।
* সার্ভারের rate limiting DOM থেকে বোঝা যায় না; লাইক নীরবে কাজ না করলে error বাড়বে —
  সেটিই থামার সংকেত।
* recognition ID-র একমাত্র উৎস `href`; না পেলে গেট ক্লিক না করে বাদ দেয়।
* শুধু মূল ডকুমেন্ট; iframe-এর ভেতরের recognition বাদ যায়।
* এটি একটি সামাজিক সংকেত অটোমেট করছে। ঢালাও লাইক সহকর্মীদের চোখে পড়বে এবং প্রতিষ্ঠানের
  নীতির বিরুদ্ধে যেতে পারে — সিদ্ধান্ত আপনার, তাই **Maximum new likes** ডিফল্ট ১০০।

**প্রথমবার আসল সাইটে চালানোর সময় Maximum new likes ৩–৫ রাখুন**, নিজে চোখে দেখে
নিশ্চিত হয়ে তারপর বাড়াবেন।
